## How EffectCraft is driven

| Manifest | EffectCraft |
| --- | --- |
| `command` | `effectcraft-cli mcp` with `--automation-read-root` / `--automation-write-root` (EffectCraft's confinement, crates/automation/src/confine.rs) |
| `tools.list` | `command_list` (bare array; 735 commands, 615 with a `params` doc; the 120 without one, e.g. `file.newProject`, are invisible to the adapter's catalogue) |
| `tools.run` | `command_run {id, params}` |
| `actions.open` | tool `open_project {path}` (.ecproj) |
| `actions.save` | tool `save_project {path}` (Save As; JSON; deterministic, and open → save is the identity) |
| `actions.close_all` | command `file.closeProject` (leaves an empty project; succeeds with nothing open) |
| `actions.clear_history` | command `edit.purgeUndo` |
| `actions.export` | command `comp.saveFrameAs` (unused by nodes; `ec.export_png` names it as its own `command`, so no `format` is sent) |
| `gui` | `effectcraft [project.ecproj]` (`PLUMCRAFT_EFFECTCRAFT_APP` overrides) |
| catalogues | `effects` = `effect.list` (307 effects; `ec.effect`'s choices), `presets` = `anim.builtinPresets` (46; `ec.preset`'s choices), both with `path = ""` (the reply is a bare array) |

## Assumptions

- Prefix `ec.`; doc wire `effectcraft.project`, ext `ecproj`, stem `project`, media `application/vnd.effectcraft+json` (the file is JSON; the type is invented).
- Layers are addressed explicitly, default `#1` (the top layer, which is where every new layer goes), never by selection: a reopened project (every cold node) has no selected layers. `layers` widgets are JSON (`["#1"]`) with sockets, so a layer id from `ec.text`'s `layer` output can be wired in via JSON.
- Effects are one node with an effect enum rather than 307 generated nodes: `effect.apply` takes no effect parameter values (the `add_effect` tool does, but it is a tool, and `generate` sends `params`), so effect parameters go through `ec.set_property` at `effects/#n/<param>`.
- No `[thumb]` (the adapter's thumb wants `artboards[0]` and a PNG export with `format`/`scale`).
- No image input: `open_project` only reads .ecproj. Importing footage (`file.import {paths}`) would need a transform that takes a staged file, which the adapter does not have.

## Open problems and adapter changes

1. **Export sends `format` unconditionally (fixed in round 2).** `nodes.rs` `export()` always inserts `"format": <node format>` into the export action's parameters. `comp.saveFrameAs` answers "invalid parameters …: unknown parameter(s) `format`; accepted: path, time, scale, queue", and the `render_frame` tool answers "unknown argument \"format\" for render_frame; expected: comp, inline, max_side, path, time, transparent". Adapter change: an `Action` field naming the format key, e.g. `export = { command = "comp.saveFrameAs", path = "path", format = "" }` where an empty (or absent-by-opt-out) `format` sends none; or per-node `export_command` so each export node names its own command (`comp.saveFrameAs` for PNG, `comp.saveFrameAsPsd` for PSD, `comp.saveFrameAsExr` for EXR, `file.exportLottie` for Lottie JSON). Per-node commands would also suit PhotoCraft and others. Once fixed, delete the `[exclude]` line; the test's `LISTED` then gains `ec.export_png`, and the demo can end in it.
2. **Video export needs two commands.** Rendering a movie is `renderQueue.add {comp, format, output}` then `renderQueue.render {wait: true}`. One action cannot express it. Adapter change: an export action that is a list of steps (`[[actions.export_video]] steps = [...]`, with `{path}` substituted), or EffectCraft could add a one-shot `comp.render {path, format, start?, end?}`. Until then MP4/GIF/WebM are out.
3. **Commands without a `params` doc are invisible.** `read_catalogue` skips entries without a string `params`, so `file.newProject`, `project.summary`, `renderQueue.list` and 117 others cannot be node commands. Adapter change: treat a missing `params` as `""` (no keys). EffectCraft-side alternative: give every command a `params` doc (`{}`).
4. `ec.effect` lists audio effects too (Bass & Treble, Reverb …); applied to a visual layer they fail with EffectCraft's own error.
